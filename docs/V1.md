# Road to Dusty 1.0

Where we are (0.3): a working tray app with whole-drive index, natural-language + voice search,
16 detectors, plans, hibernation, speed tools, auto-updates, a character with presence.
What follows is everything between "works on my machine" and "people install it and love it".

## 1. Pitch (keep every decision honest to this)

> **Dusty is a tiny housekeeper that lives on your PC.** It quietly keeps your files tidy,
> finds anything you ask for (even by voice) and makes Windows feel freshly installed again.
> Specialized, fast and **100% on your computer**: no cloud, no account, no telemetry, open source.

Not a chatbot, not an "AI that controls your PC". A small specialist that tells the truth, fast.

## 2. Must-haves before launch (blockers)

**Trust & safety**
- [ ] **Code-signing certificate** (OV/EV or Azure Trusted Signing) so SmartScreen doesn't warn;
      sign the installer *and* `dusty.exe`.
- [ ] Antivirus false-positive check (VirusTotal, submit to Microsoft/Defender) for a tool that deletes files.
- [ ] "Safety net" audit: every destructive path has undo or a two-step confirm; fuzz tests for
      path handling (junctions, long paths, OneDrive placeholders, network drives, permissions).
- [ ] Crash-safe operations: journal moves/hibernations so an interrupted action can resume or roll back.
- [ ] Never touch system/app folders except known-safe cache entries; integration tests on a VM image.

**Updates & distribution**
- [ ] Public update endpoint (GitHub Releases on a public repo or a tiny static host) +
      `scripts/release.ps1` uploading `latest.json` and the signed installer. Staged rollout (e.g. 10 % → 100 %).
- [ ] winget manifest, a simple landing page, Microsoft Store (MSIX) later.
- [ ] Clean uninstall: optional "remove my Dusty data" + restore anything still in Dusty's archive/cold storage.

**Onboarding & first run**
- [ ] First scan feels magical in < 60 s: show progress + first findings live as they arrive.
- [ ] Explain permissions, privacy and what Dusty will/won't do in plain words (one screen).
- [ ] Sample "wins" right away (temp files, installers of already-installed apps).

**Quality**
- [ ] Settings migration/versioning tests; DB schema migrations.
- [ ] Performance budgets enforced in CI: idle CPU ≈ 0 %, RAM < 200 MB with index, scan never > 5 % CPU in background, search p95 < 50 ms.
- [ ] Error reporting that is **opt-in and local-first** (save a report the user can choose to send).

## 3. Search & voice → "phenomenal"

What we have: forgiving lexical engine (name + folder coverage, synonyms EN/IT, stems,
typos, accents) at 30–45 ms over 3 M files; Moonshine/Parakeet speech on-device in ~0.3 s.

Next steps, cheapest first:
1. **Learning-to-rank from clicks:** files you open from results get a boost next time
   (per-path frecency, like browsers). Huge perceived intelligence, zero models.
2. **Recent-files signal:** Windows "Recent" items, jump lists, last-opened times as ranking features.
3. **Content search for documents:** small full-text index of text-like files (PDF/DOCX/TXT/MD
   text extraction) in user folders, built at idle with tantivy. "the pdf that mentions IBAN".
4. **Semantic re-ranking:** a tiny embedding model (e.g. bge-small / MiniLM, int8 ONNX, ~30 MB)
   embeds the *query* and the *top 200 lexical candidates' names+folders* on the fly (≈ 20 ms on CPU).
   Never embed 3 M files; rerank candidates. Optional per-folder embeddings cached at idle.
5. **Query understanding model (optional, voice only):** a ~0.5 B instruct model with grammar-
   constrained JSON output to turn rambling speech into the structured query
   (terms/types/dates/locations). Keep the rule parser as the instant first pass.
6. **Streaming voice:** live partial transcript while speaking (VAD + streaming Zipformer/Moonshine).
7. **More languages** for parsing (ES/FR/DE), localized synonyms.
8. **Answers, not only lists** (still read-only): "how big is my photos folder?", "what did I
   download yesterday?", "biggest videos on D:", with a one-line spoken answer.

## 4. Cleaning & speed: gaps people will notice

- Uninstall leftovers (AppData folders of apps that are gone), orphaned shortcuts, broken Start menu entries.
- Large old VM/WSL disks, Docker images (`docker system df`), Android emulators, old Xcode-like SDKs.
- Duplicate *folders* (whole trees copied twice) and "same photo, different format" (RAW + JPG).
- Browser downloads correlation (which page a file came from, using local browser history).
- Scheduled tasks and third-party services review; "what slows my boot" timeline (boot trace summary).
- Disk health (SMART) warnings, SSD wear, low-space early warning with a one-click plan.
- Battery-aware behaviour on laptops (never scan on battery < 30 %, smaller budgets).
- Network hogs per process (ETW) to complete the hogs picture.
- "Fresh install feeling" checklist: one page summarising startup apps, bloat, caches, drivers, Windows.old.

## 5. Organizing (what users will ask)

- **Rules builder:** "PDFs from my bank → Documents\Finance", "screenshots older than 30 days → archive".
- **Auto-file new downloads** silently once a rule is trusted (with a weekly "here's what I filed" digest).
- **Photo library mode:** sort by date into `YYYY/MM`, detect bursts, keep best shot.
- **Mirrors/backups awareness** beyond duplicates: verify that backup copies are complete.
- Undo history export ("what did Dusty do last month?").

## 6. Personality & delight (polish list)

- Painted mascot layers (see `docs/MASCOT.md`), animated blink/breathe/sweep; seasonal hats.
- Dusty reacts to events: a happy dance after big cleanups, a tiny sneeze when it finds dust,
  yawns late at night, a coffee cup when you buy it a coffee.
- Achievements/streaks that are genuinely useful ("10 GB freed", "inbox zero for a week").
- Sound design (optional, off by default): a soft broom swish on delete, a chime on "all clean".
- Wallpaper-safe desktop strolls: avoid walking over the area under the mouse; walk on top of
  the taskbar; occasional "sweeping the taskbar" gag.
- Theming: light mode polish, accent colour picker, compact mode.

## 7. Engineering optimisations

- Index memory: front-coded names + u32 sizes for small files + mmap'd arena → ~70 MB for 3 M files.
- MFT/USN fast path through an optional elevated helper service (index in seconds, exact live updates).
- Incremental duplicate hashing via USN journal; xxh3 + size + head/tail sampling for huge files.
- Thumbnail cache on disk (LRU), preview workers off the UI thread.
- Move detectors to a plugin-like registry with per-detector budgets and tests.
- End-to-end tests with a synthetic filesystem fixture; Playwright tests for the UI via the mocked backend.
- Code splitting per view; lazy-load Space/Speed.

## 8. What people will ask (FAQ to answer in-app and on the site)

- *Is it safe? Will it delete my stuff?* → Recycle Bin by default, undo, protect folders, nothing without asking unless you enable autopilot.
- *Does it upload my files or voice?* → No. Everything is local; source is open.
- *Why does it need admin sometimes?* → Only for specific tune-ups (optimize drive, hibernation…), asked each time.
- *Does it slow my PC?* → Runs when you're away, at background priority; ~0 % CPU when idle.
- *Can I use it on multiple PCs / sync settings?* → Export/import settings (planned).
- *Mac/Linux?* → Windows first; core is portable Rust, UI is web tech.
- *How is this different from CCleaner / WizTree / Everything?* → One calm tool that combines
  what they do, explains every suggestion, learns your preferences, and stays private.

## 9. Launch plan

1. Private beta (friends, ADHD communities, dev communities) with an in-app feedback button
   that opens a pre-filled GitHub issue (no data sent automatically).
2. Fix the top 10 issues; stabilise updates for 2 weeks.
3. Public 1.0: GitHub release, winget, landing page with the pitch + a 30-second video of Dusty at work.
4. Post-launch: content search, rules builder, MFT helper, painted mascot.

## 10. Success metrics (measured locally, shown to the user, never sent)

- Bytes freed per week, decisions per session, time-to-inbox-zero, search success (opened a result).
- Qualitative: "I haven't reinstalled Windows in a year".
